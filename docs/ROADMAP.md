# HR 면접 질문 사전 — 개발 로드맵 (ROADMAP)

> 이 문서는 [`PRD.md`](./PRD.md)에서 정한 "무엇을 만들지"를 바탕으로,
> **"어떤 순서로 만들지"**를 단계별로 정리한 개발 진행 지도입니다.

## 전체 흐름 한눈에 보기

| 단계 | 이름 | 한 줄 요약 | 예상 소요 시간 |
| --- | --- | --- | --- |
| 1 | 프로젝트 초기 설정 | 골격 구축 (빈 집 짓기) | 0.5일 |
| 2 | 공통 모듈/컴포넌트 개발 | 여기저기 재사용할 부품 만들기 | 1일 |
| 3 | 핵심 기능 개발 | 질문 목록 + 카테고리 필터링 | 2일 |
| 4 | 추가 기능 개발 | 검색 등 곁들임 기능 | 1일 |
| 5 | 최적화 및 배포 | 다듬고 세상에 공개 | 1일 |
| | | **합계** | **약 5.5일** |

> ⏱️ 소요 시간은 1인 개발, 하루 작업 기준의 **예상치**예요. 처음이라면 더 걸릴 수 있고, 그래도 괜찮아요.

---

## 1단계 — 프로젝트 초기 설정 (골격 구축)

### 할 작업
- Next.js 15 + TypeScript 프로젝트 생성
- Tailwind CSS, shadcn/ui, Lucide React 설치 및 설정
- 폴더 구조 정리 (`app/`, `components/`, `lib/` 등)
- 환경 변수 파일(`.env.local`) 준비 (Notion 키는 다음 단계에서 채움)
- Vercel 연결용 Git 저장소 정리

### 왜 이 순서인가요?
집을 지을 때 **빈 골조와 배선부터** 깔아야 그 위에 방을 만들 수 있어요.
개발 도구·스타일 환경이 먼저 갖춰져 있어야, 이후 단계에서 만든 코드가
바로 화면에 제대로 보입니다.

### 완료 기준
- [ ] `npm run dev`로 개발 서버가 정상 실행된다.
- [ ] 빈 페이지에 Tailwind 스타일이 적용되는 게 확인된다.
- [ ] shadcn/ui 버튼 하나가 화면에 잘 보인다.

---

## 2단계 — 공통 모듈/컴포넌트 개발

### 할 작업
- **Notion 연동 모듈** (`lib/notion.ts`): Notion API 클라이언트 + 질문을 불러오는 함수
- **타입 정의** (`types/`): 질문 데이터 모양(Question 타입) 정의
- **공통 UI 컴포넌트**: 카드, 배지(난이도·카테고리), 레이아웃(헤더/푸터) 등
- 카테고리·난이도 상수 정의 (인사/총무·채용·노무·조직문화 / 초급·중급·고급)

### 왜 이 순서인가요?
3단계의 핵심 기능은 "질문 데이터를 불러와 화면에 보여주기"인데,
그러려면 **데이터를 가져오는 모듈**과 **반복해서 쓸 UI 부품**이 먼저 있어야 해요.
부품을 미리 만들어두면, 핵심 기능에서 조립만 하면 되니 훨씬 빨라집니다.

### 완료 기준
- [ ] Notion에서 질문 목록을 콘솔에 출력하는 데 성공한다.
- [ ] Question 타입이 정의되어 자동완성이 동작한다.
- [ ] 카드·배지 컴포넌트가 독립적으로 잘 렌더링된다.

---

## 3단계 — 핵심 기능 개발

### 할 작업
- **질문 목록 페이지(홈)**: Notion에서 발행된(`Status = 발행됨`) 질문을 불러와 목록 표시
- **카테고리 필터링** ⭐: 직무 카테고리 선택 시 해당 질문만 표시 (PRD의 핵심 기능)
- **질문 상세 페이지**: 질문 내용, 의도, 좋은 답변 예시, 난이도 표시

### 왜 이 순서인가요?
이 단계가 **이 앱의 존재 이유(핵심 가치)**예요.
1~2단계에서 만든 골격과 부품 위에 핵심 기능을 올려야 안정적으로 동작합니다.
추가 기능(검색)보다 핵심을 먼저 완성해야, 중간에 멈춰도 쓸모 있는 제품이 됩니다.

### 완료 기준
- [ ] 홈에서 전체 질문 목록이 보인다.
- [ ] 카테고리를 선택하면 해당 직무 질문만 걸러진다.
- [ ] 질문을 클릭하면 상세 페이지로 이동해 의도·답변·난이도가 보인다.
- [ ] 여기까지가 **MVP 완성 지점**입니다. 🎯

---

## 4단계 — 추가 기능 개발

### 할 작업
- **면접 질문 검색**: 키워드로 질문 찾기 + 검색 결과 페이지
- 태그(Tags)로 질문 필터링 (여유가 되면)

### 왜 이 순서인가요?
검색은 "있으면 좋지만 없어도 핵심 가치는 전달되는" 기능이라 MVP 이후로 미뤘어요.
핵심이 탄탄하게 동작하는 걸 확인한 뒤에 살을 붙여야,
새 기능 때문에 핵심이 망가지는 일을 막을 수 있습니다.

### 완료 기준
- [ ] 키워드를 입력하면 일치하는 질문 목록이 보인다.
- [ ] 검색 결과가 없을 때 안내 메시지가 표시된다.

---

## 5단계 — 최적화 및 배포

### 할 작업
- **반응형 점검**: PC·태블릿·모바일에서 레이아웃 확인 및 보정
- 로딩 상태·에러 처리 보완 (Notion 응답 지연·실패 대비)
- 이미지·폰트·번들 최적화, 기본 SEO(메타 태그) 설정
- **Vercel 배포** 및 환경 변수 등록

### 왜 이 순서인가요?
최적화와 배포는 **기능이 다 완성된 뒤** 하는 마무리예요.
미완성 상태에서 배포하면 자주 다시 올려야 해서 비효율적이에요.
모든 기능이 동작하는 걸 확인한 마지막에 한 번에 다듬고 공개합니다.

### 완료 기준
- [ ] 모바일·태블릿·PC에서 레이아웃이 깨지지 않는다.
- [ ] 데이터 로딩 중·실패 시에도 화면이 자연스럽게 보인다.
- [ ] Vercel에 배포되어 실제 URL로 접속된다.
- [ ] Notion에 질문을 추가하면 배포된 사이트에 반영된다.

---

## 의존 관계 정리 (왜 거꾸로 가면 안 되나요?)

```
1단계 (골격) → 2단계 (부품) → 3단계 (핵심) → 4단계 (추가) → 5단계 (배포)
   기초              재료            본체           장식           공개
```

- 골격 없이 부품을 둘 곳이 없고,
- 부품 없이 핵심을 조립할 수 없고,
- 핵심 없이 추가 기능은 의미가 없고,
- 다 만들기 전에 배포하면 계속 다시 올려야 합니다.

그래서 **순서대로** 진행하는 것이 가장 빠른 길입니다.
